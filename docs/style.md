# Personal Web Design Style v1.1

> 이 문서는 여러 프로젝트에 반복 적용할 개인 디자인 성향을 정의합니다.
> 특정 프로젝트의 브랜드, 컬러, 콘텐츠 구조는 `docs/design.md`에서 별도로 결정합니다.
> 이 문서는 **디자인 판단이 필요할 때 참조하는 라이브러리**이며, 모든 작업에서 전체 문서를 다시 읽기 위한 체크리스트가 아닙니다.

## 0. 사용 원칙 — 토큰/컨텍스트 절약

- 오탈자, 링크, 이미지 경로, 단일 CSS 값 등 **간단하고 명확한 수정에서는 이 문서를 읽지 않아도 됩니다.**
- 기존 화면의 일부를 수정할 때는 필요한 항목(예: 타이포그래피, 카드, 여백, 모바일)만 찾아서 확인합니다.
- 신규 화면, 리디자인, 디자인 방향 결정처럼 스타일 판단 비중이 큰 작업에서만 전체 내용을 참고합니다.
- 현재 작업 흐름에서 이미 확인한 스타일 규칙은 반복해서 로드하지 않습니다.
- 프로젝트 고유 결정은 이 문서보다 `docs/design.md`를 우선하며, 현재 사용자의 명시적 지시가 가장 우선합니다.
- 컨텍스트 절약을 위해 필요한 규칙까지 생략하지 않습니다. 기존 디자인과 충돌 가능성이 있으면 관련 섹션을 확인합니다.

## 1. 스타일 목표

내가 지향하는 결과물은 **한국 사용자에게 익숙하면서도, 웹에이전시 템플릿이나 AI 생성 화면처럼 보이지 않는 실무형 디자인**입니다.

핵심 표현은 다음과 같습니다.

- 정돈되어 있지만 비어 있지 않음
- 세련되지만 과장되지 않음
- 정보가 많아도 복잡해 보이지 않음
- 한국어 타이포그래피가 주인공이 되는 화면
- 콘텐츠와 이미지가 실제 서비스처럼 보이는 구성
- 섹션마다 리듬이 있지만 하나의 브랜드처럼 연결되는 화면

---

## 2. 스타일 우선순위

1. 서비스 목적과 핵심 행동
2. 정보 구조와 탐색성
3. 한국어 타이포그래피
4. 레이아웃의 완성도와 리듬
5. 이미지와 브랜드 컬러
6. 인터랙션
7. 장식

장식이 콘텐츠 이해보다 먼저 보이면 수정합니다.

## 3. 기본 디자인 성향

### 적용 예외

아래 시각 규칙과 수치는 기본 선호이며 모든 프로젝트의 절대 조건은 아닙니다. 짧은 페이지, 단일 기능 화면, 브랜드 고유 표현, 승인된 Figma 구현에서는 서비스 목적·콘텐츠 양·브랜드 요구·구현 정확도를 우선합니다. 구성 방식의 수나 시그니처를 맞추기 위해 불필요한 요소를 추가하지 않습니다. 중요한 예외 결정만 `docs/design.md`에 이유와 적용 범위를 짧게 기록합니다.

### 3.1 전체 인상

- 기본은 밝고 선명한 화면을 선호합니다.
- 화이트와 뉴트럴 컬러를 넓게 사용하고 브랜드 컬러는 선택적으로 강조합니다.
- 해외 SaaS 랜딩 페이지보다 국내 콘텐츠 플랫폼, 브랜드 사이트, 포털, 편집형 웹진의 균형을 선호합니다.
- 지나친 미니멀리즘보다 중간 이상의 콘텐츠 밀도를 선호합니다.
- 섹션마다 같은 카드 템플릿을 반복하지 않습니다.

### 3.2 선호하는 레이아웃

- 12컬럼 또는 명확한 모듈 그리드
- 좌우가 완전히 대칭이지 않은 편집형 구성
- 제목, 이미지, 데이터, 리스트가 서로 다른 비중으로 배치되는 화면
- 섹션 제목과 콘텐츠가 같은 축을 공유하는 정렬
- 큰 이미지 한 장과 세부 정보가 결합된 큐레이션 구성
- 카드 외에도 선형 리스트, 랭킹, 타임라인, 탭, 스티키 영역을 활용한 구성

### 3.3 선호하지 않는 레이아웃

- 모든 내용을 중앙 정렬한 단조로운 화면
- Hero부터 Footer까지 같은 폭과 같은 카드 형식이 반복되는 화면
- 큰 제목만 있고 실제 콘텐츠가 거의 없는 화면
- 모든 섹션을 3열 카드로 처리한 화면
- 섹션 사이를 배경색만 바꾸어 구분한 화면
- 의미 없이 요소를 겹치거나 공중에 띄운 화면

---

### 3.4 Figma 디자인 파일의 Auto Layout 우선 원칙

- Figma 디자인 파일의 생성·수정 요청 시, 페이지의 상위 프레임부터 섹션, 컴포넌트, 내부 콘텐츠까지 Auto Layout을 기반으로 우선 구성합니다.
- 방향, 간격, 패딩, 정렬과 Hug contents·Fill container·Fixed 크기 설정으로 콘텐츠와 화면 너비 변화에 대응하도록 설계합니다.
- 겹침이나 자유 배치 등 Auto Layout만으로 표현하기 어려운 요소에 한해 absolute 배치를 사용하고, 나머지 레이아웃은 Auto Layout 흐름을 유지합니다.
- 완료 전 텍스트 길이와 프레임 너비를 바꿔 간격, 정렬, 줄바꿈이 의도대로 유지되는지 확인합니다.

---

### 3.5 Figma 메인 시안의 화면 범위와 기본 폭

- Figma 디자인 파일로 메인 시안을 요청받으면 PC 화면만 우선 생성합니다. 모바일·태블릿 화면은 사용자가 별도로 요청한 경우에만 생성합니다.
- PC 화면의 가로폭은 기본 1920px, 주요 콘텐츠 영역의 가로폭은 기본 1440px로 생성합니다. 콘텐츠 영역은 중앙 정렬하며, 1920px 화면 기준 좌우 기본 여백은 각각 240px입니다.
- 사용자가 화면 범위나 폭을 별도로 지정하면 해당 요청을 우선합니다.
- 이 기준은 Figma 메인 시안에 우선 적용하며, 문서의 일반 컨테이너 폭·반응형 지침을 근거로 모바일 시안을 자동 추가하지 않습니다.

## 4. 메인 페이지 구성 원칙

메인 페이지는 한 가지 목적을 가진 흐름으로 구성합니다.

1. **Hero** — 서비스가 무엇인지, 왜 필요한지, 무엇을 할 수 있는지 전달
2. **핵심 탐색** — 카테고리, 검색, 메뉴, 대표 서비스 등 사용자가 바로 행동하는 영역
3. **대표 콘텐츠** — 가장 중요하거나 신뢰를 만드는 실제 콘텐츠
4. **차별화 기능** — 다른 서비스와 구별되는 기능 또는 데이터
5. **재방문 요소** — 업데이트, 랭킹, 뉴스, 커뮤니티 등
6. **마무리 행동** — 가입, 문의, 등록, 탐색 등 한 가지 중심 CTA

모든 프로젝트에서 위 순서를 기계적으로 복사하지 않고, 목적에 따라 합치거나 재배치합니다.

### Hero 선호 방식

다음 방식 중 프로젝트에 맞는 하나를 선택합니다.

- 좌측 메시지 + 우측 실제 제품/콘텐츠 미리보기
- 큰 한국어 제목 + 이미지가 그리드를 가로지르는 편집형 구성
- 검색·카테고리 등 핵심 기능을 Hero 안에 포함한 기능 중심 구성
- 브랜드 비주얼과 짧은 메시지를 결합한 캠페인형 구성

피해야 할 기본형:

- 중앙 대형 제목, 작은 회색 설명, 둥근 CTA 2개, 추상 구체 이미지
- 근거 없는 `AI가 모든 것을 바꿉니다` 같은 문구
- 100vh를 채우지만 실제 정보는 적은 Hero

## 5. 타이포그래피

### 5.1 기본 원칙

- 기본 서체는 프로젝트 목적에 맞춰 `Pretendard Variable`, `SUIT Variable`, `Noto Sans KR` 중 선택합니다.
- 별도 근거가 없으면 Pretendard Variable을 사용합니다.
- 한 화면에서 한글 본문용 서체는 한 종류를 기본으로 합니다.
- 디스플레이 서체는 브랜드 성격과 라이선스가 확인된 경우에만 제한적으로 추가합니다.
- 영문만 별도의 장식 서체로 바꾸지 않습니다.

### 5.2 타이포그래피 인상

- 제목은 굵기만 키우지 않고 크기, 행간, 줄 수, 정렬로 위계를 만듭니다.
- Hero 제목은 보통 2~3줄 안에서 읽히도록 합니다.
- 한글 제목의 자간을 과도하게 좁히지 않습니다.
- 본문은 최소 15~16px, 보조 문구는 원칙적으로 13px 이상을 사용합니다.
- 회색 텍스트를 너무 밝게 사용하지 않습니다.
- 긴 설명보다 짧은 제목, 수치, 태그, 보조 설명의 조합을 선호합니다.

### 5.3 금지 사항

- `font-weight: 800~900`을 모든 제목에 반복
- 제목마다 무조건 영문 eyebrow 추가
- 본문 너비를 지나치게 좁혀 한국어가 여러 줄로 끊기는 구성
- 작은 폰트와 넓은 여백으로만 세련됨을 표현
- 줄바꿈을 `<br>`로 고정해 모바일에서 부자연스럽게 보이는 구성

## 6. 색상

### 6.1 기본 전략

- 뉴트럴 베이스 + 주 브랜드 컬러 1개를 기본으로 합니다.
- 보조 포인트 컬러는 명확한 역할이 있을 때 1개만 추가합니다.
- 한 화면의 강한 색상 면적은 전체의 약 10~20% 범위에서 조절합니다.
- 색상보다 타이포그래피, 이미지, 구획으로 위계를 먼저 만듭니다.
- 브랜드 컬러가 정해지지 않았으면 참고 사이트를 평균 내지 말고 프로젝트 주제에서 색상 근거를 찾습니다.

### 6.2 선호하는 색상 사용

- 화이트, 웜 화이트, 밝은 그레이 배경
- 검정에 가까운 강한 제목색
- 본문과 보조 정보가 명확히 구분되는 3단계 텍스트 컬러
- 한두 개의 강한 색을 버튼, 링크, 활성 상태, 핵심 비주얼에 집중
- 이미지 색감과 UI 색상이 충돌하지 않는 구성

### 6.3 피해야 할 색상 사용

- 프로젝트와 무관한 보라·파랑 그라데이션
- 보라 + 청록 + 주황을 기본 팔레트처럼 동시 사용
- 카드마다 다른 파스텔 컬러
- 회색 배경 위에 또 다른 회색 카드가 반복되는 구성
- 시각 위계 없이 모든 버튼과 배지에 브랜드 컬러 적용
- 네온, 강한 글로우, 유리 효과를 핵심 스타일로 사용

## 7. 카드, 구획, 모서리

### 카드 사용 기준

카드는 다음 중 하나가 필요할 때 사용합니다.

- 개별 항목 전체가 클릭 대상일 때
- 여러 항목을 같은 기준으로 비교할 때
- 이미지와 메타 정보를 하나의 단위로 묶을 때
- 배경과 명확히 분리해야 할 독립 기능일 때

카드가 필요하지 않은 경우에는 아래 방식을 먼저 검토합니다.

- 구분선이 있는 리스트
- 타이포그래피 중심의 편집형 배열
- 이미지와 텍스트의 2열 구성
- 테이블 또는 랭킹
- 탭과 스티키 콘텐츠
- 섹션 자체의 배경과 여백을 이용한 구분

### 모서리 원칙

- 작은 입력·버튼: 8~10px
- 일반 카드: 10~14px
- 큰 비주얼·프로모션: 16~24px
- pill은 태그, 상태, 필터처럼 의미가 있을 때만 사용
- 하나의 화면에서 2~3개 이상의 radius 체계를 만들지 않음

### 그림자 원칙

- 기본 카드에는 테두리 또는 매우 약한 그림자 중 하나만 사용
- hover에서 카드가 과도하게 떠오르지 않음
- 그림자는 모달, 드롭다운, 고정 헤더처럼 깊이가 필요한 요소에 우선 사용

## 8. 이미지와 그래픽

- 실제 서비스 이미지, 제품 화면, 콘텐츠 썸네일을 우선합니다.
- 이미지가 없다고 추상 3D 오브젝트나 AI 구체를 자동으로 넣지 않습니다.
- 이미지 크롭은 인물, 제품, 텍스트의 초점을 고려합니다.
- 목록 이미지 비율은 프로젝트 안에서 일관되게 사용합니다.
- Hero 이미지는 단순 장식이 아니라 서비스 성격이나 콘텐츠를 설명해야 합니다.
- 아이콘은 하나의 세트와 선 굵기를 유지합니다.
- 장식 아이콘은 최소화하고 텍스트를 대신하지 않습니다.

---

## 9. 정보 밀도와 여백

- 메인 컨테이너는 일반적으로 1200~1320px 범위에서 결정합니다. 단, Figma 메인 시안은 3.5절에 따라 콘텐츠 폭 1440px을 기본으로 합니다.
- 섹션 간격은 기본 72~96px를 사용하되 모든 섹션을 같은 간격으로 만들지 않습니다.
- 콘텐츠 내부 간격은 8px 단위 계열을 기본으로 사용합니다.
- 여백은 내용을 숨기는 장식이 아니라 정보 그룹을 구분하는 도구로 사용합니다.
- 모바일에서는 데스크톱 여백을 단순 축소하지 않고 핵심 정보 순서를 다시 정합니다.

---

## 10. 인터랙션과 모션

- 인터랙션은 사용 가능 여부와 상태 변화를 설명해야 합니다.
- 버튼과 링크는 150~220ms, 카드와 메뉴는 180~280ms를 기본 범위로 합니다.
- 스크롤 등장 애니메이션은 필요한 핵심 영역에만 제한합니다.
- 모든 섹션에 동일한 fade-up을 반복하지 않습니다.
- hover 효과는 위치 이동보다 색상, 선, 이미지 확대 1~2% 등 절제된 변화를 선호합니다.
- `prefers-reduced-motion`을 지원합니다.

---

## 11. 한국어 UI 문구

- 번역투 표현보다 실제 국내 서비스에서 사용하는 자연스러운 문구를 사용합니다.
- 버튼은 결과가 명확한 동작형 문구를 사용합니다.
- `Learn more`, `Explore`, `Discover`를 무조건 `자세히 보기`로 반복하지 않습니다.
- 같은 행동에는 같은 용어를 사용합니다.
- 제목과 설명에서 같은 내용을 반복하지 않습니다.
- 숫자, 날짜, 가격, 상태처럼 실제 화면에 필요한 정보를 포함합니다.

---

## 12. 개인 스타일 시그니처

프로젝트에 적합할 때 아래 중 한 가지를 선택해 일관되게 사용합니다. 짧은 페이지나 승인된 디자인 구현에는 별도의 시그니처를 강제하지 않습니다.

- 강한 한국어 제목과 얇은 구분선이 결합된 섹션 헤더
- 이미지가 컬럼 경계를 일부 넘는 편집형 레이아웃
- 리스트의 순번, 카테고리, 날짜를 타이포그래피 요소로 활용
- 스티키 제목과 스크롤 콘텐츠의 조합
- 한 개의 브랜드 컬러 면과 뉴트럴 콘텐츠 영역의 대비
- 큰 이미지 1개와 작은 정보 단위가 연결되는 비대칭 그리드

여러 시그니처를 동시에 과도하게 사용하지 않습니다.

## 13. 최종 거절 기준

아래 특징이 강하면 결과물을 승인하지 않고 수정합니다.

- 어떤 AI 서비스 랜딩 페이지에도 적용 가능한 화면
- 참고 사이트의 표면적인 색과 카드만 섞은 화면
- 브랜드명과 문구를 바꾸어도 동일해 보이는 화면
- 모든 요소가 둥글고 떠 있는 화면
- 실제 콘텐츠가 들어가면 무너질 정도로 정보량이 적은 화면
- 한글 제목과 본문의 균형이 맞지 않는 화면
- PC 화면만 보기 좋고 390px에서 구조가 무너지는 화면

## 14. 스타일 라이브러리 업데이트 방법

승인한 디자인이 생길 때마다 이 문서 하단에 다음 형식으로 추가합니다.

```text
[승인 패턴]
- 사용자 승인 날짜:
- 프로젝트 / 화면 / 버전:
- Figma 링크와 노드 또는 스크린샷 절대 경로:
- 적용 화면 너비: Desktop / Tablet / Mobile
- Hero 유형과 콘텐츠 구성:
- 폰트: 서체 / 크기 / 굵기 / 행간 (Desktop / Mobile)
- 레이아웃: 컨테이너 폭 / 좌우 여백 / 섹션 간격 / 그리드 간격
- 색상: 역할별 HEX 또는 토큰명
- 컴포넌트: 카드·리스트 사용 위치 / radius / 상태 표현
- 유지할 요소와 이유:
- 다시 사용하지 않을 요소와 이유:
- 재사용 가능한 조건 / 프로젝트에만 적용할 예외:
```

개인의 취향이 명확해질수록 추상적인 형용사는 삭제하고 실제 승인 사례와 수치로 교체합니다.

## 15. 승인 패턴 기록

아직 확정된 패턴 없음. 첫 번째 사용자 승인 디자인부터 누적합니다. 자체 검수 통과를 사용자 승인으로 기록하지 않습니다. 확인되지 않은 수치나 링크는 미확정으로 남깁니다.

# LIVEPATCH Visual Patch Studio · 명령 입력창 및 감싸는 레이어 상세 계약 (v5.6)

> 적용 위치: 고객 콘솔 `C13` 및 인페이지 레이어 `O09~O20`. 본 장은 Studio의 사용자 노출 요소와 실행 동작을 규정합니다. 구문분석 엔진·큐·DB 등의 서버 전용 모듈은 페이지로 집계하지 않으며, 화면과 연결되는 데이터 계약만 기술합니다. 새로운 치수·한도·정책은 **확정 전 설계 제안**입니다. **v5.6:** 마스터 4-1·9-3과 충돌하던 치수·상태·명령 유형·음성·복원 규칙을 마스터 24-3 정본에 맞춰 수정했습니다.

## 23-1. Studio의 최상위 편집 원칙

- **미리보기와 배포를 분리**합니다. `변경안 생성`은 오직 Draft/Preview를 생성하며 운영 사이트를 변경할 수 없습니다. `운영 반영`은 별도 승인과 안전 검사가 필요합니다.
- **명령은 반드시 맥락을 가집니다.** `조직 ID`, `사이트 ID`, `환경`, `URL`, `선택 요소`, `변경 의도`, `적용 범위`, `사용자 ID`, `작업 ID` 중 해당하는 값을 누락한 상태에서 자동 운영 배포로 이어질 수 없습니다.
- **원본 매핑이 불명확하면 묻습니다.** 후보 소스가 복수이거나 매핑 `LOW/UNKNOWN`이면 원본 수정은 자동 진행하지 않습니다. 선택 후보와 영향 범위를 사람이 확인하거나 전문가 작업으로 전환합니다.
- **사용자가 닫아도 데이터는 남아야 합니다.** Dock 닫기=UI 숨김, 작업 취소=취소 가능 단계에 한함, 이미 배포된 변경의 취소=새 롤백 트랜잭션으로 명확하게 구분합니다.
- **크레딧 상태는 거래 단계대로 표시**합니다. 예상 금액 → 보류(HOLD) → 확정 차감 또는 반환을 서로 다른 수치·레이블로 보여줍니다. **확정 차감은 예상 크레딧을 넘지 않습니다(v5.6).**
- **1인 조직도 배포할 수 있어야 합니다(v5.6).** `ORG_OWNER`는 재인증 후 본인 승인할 수 있고, 조직 설정으로 2인 승인을 강제할 수 있습니다.
- **반영 방식을 항상 보여줍니다(v5.6).** 선택 영역 근처와 Dock에 `원본 수정`·`CMS 필드 변경`·`표시 패치(원본 미수정)` 배지를 상시 표시합니다.

## 23-4. 명령 작성(Inspector) 데이터 스키마와 필드 종속성

```ts
// 외부 API 확정 전 프런트엔드/서버 합의용 예시 DTO
interface PatchInstructionDraft {
  organizationId: string;
  siteId: string;
  environment: 'production' | 'staging' | 'test';
  pageUrl: string;                      // 검증된 사이트 도메인만
  selectedNodeId: string | null;       // element select 전에는 null
  selectedNodeFingerprint?: string;    // DOM이 바뀌었는지 검사
  operationKind: 'auto' | 'text' | 'style' | 'layout' | 'image';   // v5.6: 'other'는 전문가 요청 경로로 분리
  naturalLanguageInstruction: string;  // 2~3000자: 제안 제한
  scope: 'selected_element' | 'component_instances' | 'current_page';
  structuredParams?: {
    newText?: string;
    styleProperty?: 'color'|'background-color'|'font-size'|'margin'|'padding'|'text-align';
    styleValue?: string;
    uploadedAssetId?: string;
    altText?: string;
    decorativeImage?: boolean;
  };
  sourceCandidateId?: string;          // 후보가 확정된 경우만
  previewOnly: true;                   // 이 타입에서 false 허용 금지
  clientRequestId: string;             // 중복 클릭 보호
  expectedCostVersion?: string;         // v5.6: 확정 차감 상한
  approvalPolicy?: 'self_with_reauth' | 'two_person';  // v5.6: 조직 설정값(서버 판정)
}
```

| 명령 종류 | 추가로 나타나는 필드 | 입력 조건 | 막아야 할 상황 |
|---|---|---|---|
| 문구 바꾸기 | 기존 문구(읽기전용), 새 문구, 글자수, 줄바꿈 처리 | 현재 요소와 실제 데이터 소스가 일치해야 함 | 동일 문구가 3곳인데 범위가 불명확한 경우 |
| 색·폰트 변경 | CSS 속성, 값, 단위, 화면별 적용 | 색상: 허용 CSS 색 값; 크기: 허용 단위와 상한을 정책으로 검증 | `!important` 무분별 주입, 다른 브레이크포인트 전체 파손 |
| 여백·정렬 변경 | 대상 레이아웃, 축, 값, 미리보기 | 숫자·단위 및 반응형 제약을 함께 검사 | 다른 콘텐츠/버튼을 가리는 변경 |
| 이미지 교체 | 원본 이미지, 새 파일, 크롭 방식, alt, 장식 여부 | 파일 MIME·크기·EXIF·서명URL·대체텍스트 정책 | 업로드 실패로 원본 이미지 삭제/손상 |
| 여러 요소 동시 변경 | 매칭 개수·목록·대상 체크 | 개별 요소 확인 또는 명시적 범위 승인 | 사용자가 한 버튼만 선택했는데 전체 버튼이 변경되는 경우 |
| 연결 불가/원본 미확정 | 후보 소스·검증 근거·이유 | 매핑 `LOW/UNKNOWN`이면 운영 배포 금지 | 채팅 문장만으로 근거 없는 소스 파일 임의 수정 |

**필드 활성화의 순서:** `선택 요소 → 명령 입력 → 적용 범위 → 추가 속성 → 의도 재확인(필요 시) → 비용 예상 → 미리보기 생성 → 비교·검증 → 승인 → 운영 배포`. 차례가 어긋난 요청은 서버에서도 거부해야 합니다.

## 23-7. 상태 전이·동시 실행·차감 게이트

| 현재 상태 | 화면의 핵심 조작 | 다음 상태 | 금지/주의 조건 |

## 23-9. 릴리스 전 책임자들이 확정해야 할 질문

- 명령 최대 글자수, 사용자별 기본 샘플 명령 개수, 다중 요소의 묶음 상한은 얼마인가?
- `mappingGrade=MEDIUM`의 승인 정책은 자동/수동 중 무엇인가? HIGH에서도 어떤 검사 실패는 즉시 차단하는가?
- 크레딧은 어떤 이벤트에서 `HOLD`, `COMMITTED`, `RELEASED`로 전이하는가? 무료 실패 재시도 정책은 무엇인가?
- 배포 권한과 승인 권한을 동일 인물에게 줄 것인가? 조직의 마지막 Approver 퇴사 시 대체 흐름은 무엇인가?
- CSS 변경 허용 속성·단위·브레이크포인트·접근성 대비 기준은 무엇인가?
- 미리보기 브라우저와 외부 사이트 인증/iframe 제약에서 구동이 불가능한 환경을 어떻게 고객에게 설명하는가?
- 고객 API 키를 쓰는 경우 모델 비용·크레딧 차감·기록 보존 정책은 무엇인가?
- 작업 중 고객 페이지 이동/로그인 만료/원본 버전 갱신 시 어떤 작업을 자동 중단시키는가?

**v5.6 권고 출발값(확정 아님):** 명령 최대 3000자(데모 1000자) · 다중 요소 묶음 상한 20개 · `MEDIUM`은 수동 확인 후 진행, `HIGH`도 S1~S3 실패 시 즉시 차단 · HOLD는 생성 요청 시, COMMIT은 PREVIEW_READY, RELEASE는 실패·취소·HOLD 만료(30분) · 1인 조직 본인 승인 허용(재인증) · CSS 허용 속성은 color/background-color/font-size/font-weight/margin/padding/text-align/gap, 단위 px·rem·%, 대비 4.5:1 미만 결과는 경고 · 페이지 이동·로그인 만료·원본 해시 변경 시 진행 중 미리보기는 `STALE`로 표시하고 재생성 유도.

## 23-10. 키보드리스 편집 레이어 (v5.6-r2 정본)
